# Hackathon Rules and Evaluation

Last updated: 2026-08-21

Source: organizer hackathon-rules and benchmark/evaluation screenshots supplied by the user on 2026-08-21.

## Participation and access

- Remote participation is allowed.
- Lunit assets, including the provided endpoint and dashboard, cannot be accessed from outside the Lunit network.
- Do not assume that remote participation implies remote access to those assets; the required network-access mechanism has not yet been documented here.

## Mandatory model and tooling

- The final output must be generated using Lunit's L2 LLM.
- The organizer-provided Codex must be used as the coding agent.
- The development harness may be freely selected and configured during development.

Other models, tools, or deterministic processing may support orchestration only if doing so remains within the rules. They must not replace L2 as the generator of the final output.

## Data-source policy

- In addition to the provided MCP tools, external data sources may be used when the team has an appropriate license.
- This permission does not override the isolated evaluation environment. The submitted runtime must not depend on reaching an external data source during evaluation.
- If licensed external data is included offline, verify that its license permits redistribution or packaging in the submission and that it remains compatible with Docker build-time and image constraints.

## Submission and award tracks

- A single submission is used for both the Benchmark and Frontier award tracks.
- Optimize one robust artifact for both automated benchmark performance and expert-reviewed chat quality; there is no separate submission per track.

## Prohibited behavior

- Excessive reverse engineering of the HealthBench benchmark is prohibited.
- If organizer code review identifies this behavior, the team loses award eligibility.
- Do not attempt to recover hidden test items, reconstruct the holdout set, encode benchmark-specific answer keys, probe the evaluator to infer hidden examples, or add brittle case matching aimed at HealthBench items.
- General medical reasoning improvements, documented validation-set debugging, safety work, and ordinary evaluator compatibility testing remain distinct from hidden-test reverse engineering.

## Validation during the hackathon

- The dashboard can test the solution against an organizer-designated validation set during the hackathon.
- Use dashboard trials to measure benchmark performance, debug the solution, and confirm the artifact runs on the evaluation server.
- Treat validation results as development feedback, not as authorization to reconstruct HealthBench or overfit individual cases.

## Final evaluation

- The last submission transmitted through the dashboard is the final submission.
- The final artifact is evaluated on a separate HealthBench holdout test set defined by the organizers.
- The same artifact is also used for expert evaluation of chat quality.
- Evaluation runs in a completely isolated environment and external access is not permitted.

## Architecture implications

- Keep all required application code, prompts, configuration defaults, and permitted static resources inside the submitted image or supply them through an organizer-confirmed mechanism.
- Do not depend on public APIs, remote databases, package downloads at container startup, telemetry services, or web retrieval during evaluation.
- Preserve a clear path showing that L2 generated the final assistant content, even when MCP results or permitted offline data inform it.
- Favor generalizable orchestration and conversation quality over benchmark-specific branches.

## Rule-compliance checklist

- [ ] Every final assistant response is generated by L2.
- [ ] The evaluation runtime works with external network access disabled.
- [ ] Any non-organizer data has an appropriate license and permitted packaging/use.
- [ ] The harness requires no unapproved external service at evaluation time.
- [ ] One submitted artifact supports both Benchmark and Frontier evaluation.
- [ ] Validation usage and code contain no HealthBench holdout reconstruction or benchmark-specific answer keys.
- [ ] The intended final version is the last dashboard submission.
- [ ] Both benchmark behavior and expert-reviewed chat quality have been tested.
