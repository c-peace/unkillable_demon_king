# Submission and Evaluation Specification

Last updated: 2026-08-21

Source: organizer submission-page screenshots supplied by the user on 2026-08-21.

## Confirmed deliverable

- Submit a **containerized multi-turn conversation driver**.
- The evaluator sends each conversation turn to the service.
- The driver must use the conversation context to orchestrate the model and/or tools needed by its approach, then return the next assistant response.

## Container contract

- A file named `Dockerfile` must exist at the repository root.
- The image must finish building within 5 minutes on the evaluation VM.
- The container must start without a separate manual initialization step.
- The service must listen on `0.0.0.0:8000`.
- Evaluation targets container port `8000`.
- The Dockerfile must expose port `8000` (`EXPOSE 8000`).

The screenshot's `python:3.13-slim`, FastAPI/Uvicorn command, and image tag are examples, not confirmed mandatory implementation choices.

## Minimum HTTP API

The service must provide an OpenAI-compatible API with at least:

- `GET /v1/models`
- `POST /v1/chat/completions`

Do not assume unspecified optional OpenAI API features are required or supported. Confirm request fields, response schema details, streaming behavior, tool-call behavior, authentication, and error expectations from additional organizer material or evaluator evidence.

## Required branch and evaluation inputs

- Submission branch: `lunit/hackathon-submission`
- Evaluation requires the full 40-character SHA of that branch's HEAD commit.
- Evaluation also requires the model name used by the driver.
- The confirmed L2 API model identifier is `Lunit/L2-preview`; use this submission value if it remains the driver's configured model.
- A trial and its model name are saved and reused for official evaluation.
- The last submission made on the submission page is treated as the final submission.

## Submission readiness checklist

- [ ] Repository root contains `Dockerfile`.
- [ ] Clean image build completes in under 5 minutes in a suitably constrained environment.
- [ ] Container starts without manual initialization.
- [ ] Service binds to `0.0.0.0:8000` and the Dockerfile exposes `8000`.
- [ ] `GET /v1/models` returns an OpenAI-compatible successful response.
- [ ] `POST /v1/chat/completions` returns an OpenAI-compatible successful response.
- [ ] A multi-turn test demonstrates that the driver uses supplied conversation context.
- [ ] The final assistant content is generated by Lunit L2.
- [ ] Organizer model/MCP calls work from inside the container.
- [ ] The runtime succeeds with external network access disabled, aside from any organizer-confirmed internal connectivity.
- [ ] Failure and timeout behavior has been exercised without crashing the service.
- [ ] The evaluator does not inject the team key; repository-root `.env` is bundled into the private submission image and chat works without `docker run -e` or `--env-file`.
- [ ] Submission branch is exactly `lunit/hackathon-submission`.
- [ ] The submitted SHA is the branch HEAD and is exactly 40 hexadecimal characters.
- [ ] The submitted model name matches the driver configuration.
- [ ] No Patient Simulator dependency exists in the evaluation runtime path.
- [ ] The intended final trial is the last submission recorded on the page.
